### BUG-P11-1 独立复现

测试仅使用 `/private/tmp/p11-qa-*` 与 `/private/tmp/p11-qa-repro-data`；handler-like 测试首行断言 `data_root` 位于系统 tmp。

实际：`DEBOUNCE_S=0.25`；投递记录为 `size_at_delivery=1024, final_size=8192`；等待前后投递数 `1→1`，无重投。对照组先完整写入 8,192 bytes 再触发事件，记录为 `[8192]`，立即投递。

期望：文件复制完成并稳定后才投递，或至少在完成后再次投递；实际是半文件先投递、后续事件被抑制。

定级判据：主路径“把视频丢进监听目录”会出现无提示、需人工 touch/重启才能恢复的漏任务；影响自动发现但不阻塞已存在任务处理，定为 **P1**，不是 P0。

## S4｜【新发现·独立实证】P2-a／P2-b 应合并为一条 P2，且「vault 安全」被证伪

真机实验（端口 **8933**，新 tmp 根，faststart 视频，写 6,261,408 B → **停 40s** → 续写至 12,522,817 B）：

- 半截 run（`src_f74962bd…`，快照 6,261,408）**未经拦截走完 raw→render 并 `PUBLISHED`（`pub_890998edb90b`）**，vault 落 **402 字节截断稿**（只含前 ~15s 音频的转写）；
- 完整 run（`src_91e67864…`，快照 12,522,817）→ **`PUBLISH_BLOCKED`**（撞上已存在的同名笔记，No-Clobber 只判不写）→ **正确的完整笔记进不去**；`run_summary = {total:3, done:1, failed:2}`。
- **对照组**（端口 **8932**，同形状但**只停 10s**）：半截 run **无 job 目录**（gate1 拦下）、完整稿 617 字节正常入库 → **行为正确**。
- **根因一句话**：两道门都是**运动检测**（size/mtime 变没变），「长时间静止但内容不完整」的写方在原理上判不出来；触发条件是「**停顿 > 投递门 7s ＋ 半截件自己跑完转写的时间**」（本例 15s 音频 ≈ 40s），所以**短音视频比长视频更容易撞**（长视频半截要转写几分钟，写方通常早已续写、被 gate2 拦住）。
- **结论**：reviewer §R5 的 **P2-b「停顿 ≥7s → vault 安全」不成立**，它与 P2-a 是**同一根因、同一后果**（截断稿永久留在笔记库 ＋ 完整稿被 No-Clobber 挡住 ＋ 用户只看到误导性的「检查笔记库权限」提示），应**合并为一条 P2**。P2 定级我认可（高影响、低概率、根治需 Change B），但**措辞必须更正，且不得静默挂账**。
