# 故障排查

目标读者：启动失败、转写报错或任务失败时来找答案的人。
为什么独立成篇：报错种类多，README 放不下；这里只收仓库能验证的几种。

## 1. 点开始转写报 400 PRECHECK_MLX_MISSING

含义：当前 Python 里没有 `mlx_whisper`，转写跑不起来。

做法：

1. 关掉控制台。
2. 进到带 `mlx-whisper` 的 Python（`start.sh` 会优先找 `stage0bench/bin/python`、`./.venv/bin/python`、`./venv/bin/python`）。
3. 确认 `python -c "import mlx_whisper"` 能通过，再跑 `./app/start.sh`。

## 2. 提示缺 ffmpeg

含义：提取音频那步依赖本机 `ffmpeg`。

做法：先装好 `ffmpeg` 并确认命令行能找到，再重跑失败任务。

## 3. 打开 http://127.0.0.1:8899/ 没反应

- 确认 `start.sh` 还在运行，没有被 `Ctrl+C` 关掉。
- 确认端口没被别的服务占用；默认端口是 `8899`，若与别的服务冲突，用环境变量 `V2O_PORT` 指定其它端口后重跑 `./app/start.sh`（会透传给 `app/server.py`）。
- 换个浏览器或无痕窗口试一次，排除缓存问题。

## 4. 重启后监听停了

这是当前行为：监听状态只在内存里，服务重启后需要手动重新点**开始监听**。路径一般会自动回填。

## 5. 任务失败了

- 先在任务列表看该行的错误信息，点重试单独重跑一次。
- 真机曾出现多单失败的情况，原因需要重跑复现定位；不要直接删数据目录，保留现场更容易查。
- 测试只用外置目录和合成小文件，不要把用户真实目录或正式 Obsidian 库当试验场。

## 6. 转写文字有错

当前保证的是“流程能跑完”，不保证词级准确率。先用词汇区加“错词→正词”并重跑；长视频的整体准确率仍在验收中。
