## P0（主流程阻断/数据安全）

### UX2-P0-1 67个任务只看到20个，剩下的失败藏哪了我找不到
- 用户一句话：作为连跑67个的人，我只看到20行，剩下的失败去哪了我找不到。
- 现状：前端`/api/status`不传limit，后端默认20（最大200），67即47隐藏，无总数、无“只显示20/共67”、无更多/分页；P2-5搜索若做也只能搜可见20。
- 验收口径：①前端status必带`limit=200`（或分页＋总数），列表头一行“共N个（成功A/失败B/排队C），当前显示M个”；②67合成（20＋47）重放：总数＝67，可见＝67，失败16行行行可点重试；③截断时必须明示“仅显示前M个”，禁静默丢。
- 与上一轮关系：新问题（规模）。上一轮UX-P1-8/UX-P2-5按单页全可见假设，UX-FIX未补limit，本轮为其前置。

### UX2-P0-2 我点一下清空就丢了整目录历史，重起全要重转几小时
- 用户一句话：作为攒了67条的人，我点一下清空整目录就没了，重起全要重转几小时。
- 现状：`清空本目录任务`删该input下sources/runs/修订/publish/archive＋jobs盘（源视频与vault md不动），双confirm后不可撤销；重起后文件当新任务全重发现，whisper全重跑；且把空归属/孤儿run/NULL archive全带走（他目录挡门行也被清），提示“本目录N个”与实删不一致。
- 验收口径：①清空前明示代价：“将删DB N条＋jobs M个，vault md与源视频不动，但重起需重转约X分钟（按N×均耗时估），失败16条建议先用‘重试全部失败’”；②新增“只重试失败/只清失败”二选一，默认不选全清；③清后给“已清N条，源视频与笔记未动”＋撤销指引（重转前可换回旧data_root）；④qa：67库点清空必须先见代价行，选只清失败则成功51不动。
- 与上一轮关系：新功能（V2.2后清空）。上一轮无清空项，不重复。

## P1（重要体验/效率）

### UX2-P1-1 列表里看不到输出路径，一行行点开才找得到md
- 用户一句话：作为要收51个md的人，列表只给按钮不给路径，我要一行行点开才找得到。
- 验收口径：输出列每行给截断路径（一行省略＋title全路径），详情保持复制按钮；67行扫一眼能对上文件名→路径；qa：PUBLISHED/RENDER_ONLY各1行列表即见路径。
- 与上一轮关系：上一轮UX-P0-3只保详情四行，列表“输出列或行内链接”当时以按钮验收，本轮为规模下的延续（非重复）。

### UX2-P1-2 16个失败只能一个个点重试，没有一键全重试也没有导出原因
- 用户一句话：作为有16个失败的人，我只能一个个点，没有一键全重试，也导不出原因去查。
- 验收口径：失败数＞1时列表头给“重试全部失败（N个）”（调已有retry逐个幂等，后端可复用单接口循环，前端给进度“3/16已排队”）；＋“复制全部失败原因”（文件名＋原因＋下一步文本）；qa：16失败合成库点一次全回排队，原因文本可粘贴。
- 与上一轮关系：上一轮UX-P1-1只保单行重试幂等，本轮为批量（非重复）。

### UX2-P1-3 入库受阻那行同时有“重试”和“重跑”，我不知道该点哪个
- 用户一句话：作为看到入库受阻的人，那行同时有重试和重跑，我不知道该点哪个。
- 验收口径：PUBLISH_BLOCKED行只留一个主按钮“重试入库”，重跑（应用新词库）收进详情“高级”或改名“应用新词库重跑（含提示转写0次）”；行内禁两相似动词并排；qa：点行只见一主一次，文案搜“重试/重跑”不并列。
- 与上一轮关系：新功能（V2.5重跑）。上一轮只有重试，无重跑概念，不重复。

### UX2-P1-4 笔记预览看不出“我在库里改过会被跳过”，重跑完才知道没更新
- 用户一句话：作为在库里改过笔记的人，预览看不出会被跳过，重跑完才知道没更新。
- 验收口径：预览头加状态行：未改→“库内未改，重跑会更新”；已改→黄条“库内你改过，重跑会跳过不覆盖，新稿只留数据目录”；复用后端`skipped_user_edited/BLOCKED_OUTPUT_CONFLICT`判定，只读不落盘；qa：手写改vault md后预览即见黄条。
- 与上一轮关系：新功能（V2.5 No-Clobber）。V2.5-QA U-5记为措辞P2，本轮升为预览缺位P1（注明来源）。

### UX2-P1-5 停了监听后列表混着多个文件夹的任务，分不清哪行是哪的
- 用户一句话：作为试过多个文件夹的人，停了后列表混在一起，分不清哪行是哪的。
- 验收口径：停后列表每行给输入目录尾段（如“…/待转写A”）或按input分组头；未监听时总数按input分组（成功/失败分input计）；qa：A/B各转2个停后，4行行行有归属。
- 与上一轮关系：上一轮UX-P0-2只保监听态过滤（他目录不混计数），停后混合为新缺口（非重复）。

### UX2-P1-6 我点了停止，长视频到底停没停、重起会重头还是接着来没人说
- 用户一句话：作为转长视频中途想停的人，我点了停止，它到底停没停、重起会重头还是接着来没人说。
- 验收口径：点停止后给三段式：“已停止接新任务，当前这个（文件名）会跑完收尾/下轮重头（以实现为准二选一写死），重起后已完成跳过、半截重转”；运行中点停止禁立即变“未监听”误导，须先“正在收尾…”再切；qa：60s切片转中点停止，文案与终态一致。
- 与上一轮关系：上一轮UX-P0-2只保停按钮可换路径，本轮为停语义（非重复）。

### UX2-P1-7 来源那列是一串哈希，我对不上是哪个视频文件
- 用户一句话：作为看67行的人，来源那列是一串看不懂的码，我对不上是哪个视频。
- 验收口径：来源列改显视频文件夹尾段＋文件名（复用已有source_filename/映射），哈希收进title；全页source_id裸哈希零裸露（代码内除外）；qa：全文搜32位哈希列零命中。
- 与上一轮关系：上一轮UX-P0-6/UX-P1-8清了状态与报错黑话，来源列哈希漏网（注明，非重复）。

### UX2-P1-8 进度条失败也算完成，16个失败它也显示100%，我以为全成了
- 用户一句话：作为有16个失败的人，进度条也显示100%，我以为全成了。
- 验收口径：进度条分段（绿成功＋红失败＋灰排队），文案“成功A/失败B/排队C，共N”，100%仅当排队0且失败0，或明示“已收口（含失败B）”；qa：67中16失败收口时条非全绿且文案含失败。
- 与上一轮关系：上一轮UX-P0-5只保人话五步＋心跳，本轮为失败语义（非重复）。
